# hud Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the `hud` mod (Runway, compact) in the `cloudkoders/claude-mods` marketplace: a card above the message box with context, 5-hour and weekly limits with pace and projection, and session cost.

**Architecture:** Three files under `plugins/hud/hooks/`. `model.ts` turns raw usage into view values and text (pure, no `$`). `draw.ts` turns view values into SVG strings and terminal block runs (pure). `register.tsx` owns events, `$.state`, the `/hud` command, the buttons and the `AbovePrompt` drawing for desktop and terminal.

**Tech Stack:** Claude Code mod API (engine 2.1.316, `claude-code` types), TypeScript/TSX ES modules, `claude-code/testing` run by `claude plugin test`.

**Spec:** `docs/superpowers/specs/2026-10-31-hud-design.md`. Visual reference: `docs/mocks/hud-runway.html`.

## Global Constraints

- Plugin name `hud`, version `0.1.0`, license MIT, author `CloudKoders`. Marketplace name `claude-mods`, owner `CloudKoders`.
- Module files are `.ts`/`.tsx` ES modules; files import each other with static `import` only (a module holding `import()` does not load). No DOM or Node APIs; everything outside goes through `$`.
- Types come from `'claude-code'` (empty at run time); value types from `'../types'`.
- Hues: context `#8B7CF6`, 5-hour `#12B5CB`, weekly and any other limit `#4F86F7`, warn `#FFA51F`, hot `#FF4F4F`.
- SVG neutrals (must work on light and dark): track `rgba(128,128,128,0.22)`, pace tick `#8E8E93`, projection dot hollow (`fill="none"`).
- Each `Svg` source is under 131072 characters and every `Svg` has an `alt`.
- Levels: hot if used ≥ 90 or the limit runs out before reset; warn if used ≥ 70 or projected ≥ 95; else ok. Context: hot ≥ 90, warn ≥ 70.
- Projection hidden while elapsed share < 0.10. Burn rate hidden until the session is 5 minutes old. Sparkline hidden under 3 readings, keeps the last 24.
- Readings refresh on `session.measure`, `turn.complete` and a 30 000 ms clock. Breakdown (`{ breakdown: 'summary' }`) refreshes on `turn.complete` only.
- Fresh start confirm window: 5 000 ms.
- Copy is sentence case. Lane labels: `Context`, `5-hour`, `Weekly`, `Spend` (for `spend_limit`), otherwise the raw kind.

## Review Focus

1. **A reading taken just before a window rolled over** (`resetsAt` already in the past): elapsed clamps to 1, projection equals used, and reset text never shows a negative span (`resets in 0m`). Test in Task 1.
2. **A spend limit past 100%** (`percentUsed: 112`): the bar fills to the end, the text shows `112%`, the level is hot, and there's no tick or projection. Tests in Tasks 1 and 2.
3. **No context figure yet** (`context.percent` undefined before the first response): the context lane shows `—` and `1M window`, and the rest of the card still draws. Test in Task 3.
4. **A narrow terminal** (`bodyColumns: 60`): terminal bars drop to 10 cells and the detail truncates instead of wrapping. Test in Task 3.
5. **No cost ledger** (`cost` absent): the session column shows the time only, with no sparkline and no rate. Test in Task 3.

  export function span(ms: number): string                  // '9m', '1h 17m', '2d 4h'; never negative
  export function tokens(count: number): string             // '950', '97k', '1M', '1.5M'

- [ ] **Step 4: Implement `model.ts`**

`limitView`: label from the kind; with `resetsAt` and a known window, `elapsed = clamp(1 - (resetsAt - now) / WINDOW_MS[kind], 0, 1)`; `projected = used / elapsed` only when `elapsed >= 0.1`; when `projected > 100`, `runsOutAt = now + (100 - used) / (used / (elapsed * WINDOW_MS[kind]))`. `whenText` and `clockTime` round to the nearest minute. `alertText` takes the first view with `runsOutAt`, names it by its spec label (`5-hour limit`, `Weekly limit`, `Spend limit`), gives `whenText(runsOutAt)` and `span(resetsAt - runsOutAt)`, and appends ` Context is N% full.` when context ≥ 70. `resetText` and `modelName` follow the angomedia `session-hud` rules (within a day `resets in …`, under six days `resets Thu 5 PM`, else `resets Oct 21`).

Behavior, per the spec's Data flow, Surfaces, Buttons and Failure handling sections:

- Atoms under plugin `hud`: `reading` (null), `breakdown` (null), `costHistory` ([]), `turn` ({}), `isOn` (true), `action` ('idle').
- `refresh($)`: `$.session.usage()`, `$.session.model()` and `$.clock.now()`; builds a `Reading` with `at` floored to the minute; writes only when its JSON differs; appends `cost.usd` to `costHistory` when it differs from the last entry, keeping 24. Errors are swallowed (the last good state stays).
- `refreshBreakdown($)`: `$.session.usage({ breakdown: 'summary' })`; segments are the categories with `kind === 'used'`, in order, as `{ name, tokens }`; `autoCompactAt = autoCompactThreshold / context.window` when present. Errors leave the old value.
- Hooks: `session.start` (register the command, restore `isOn` from `$.store.get('isOn')`, `action` to idle, first refresh, `$.clock.every(30_000, …)`), `session.measure` (refresh, then `next(e)`), `turn.complete` (`next(e)` first, then refresh and refreshBreakdown), `turn.step` main thread only (record model and effort, as `session-hud` does), `command.run` for `hud`.
- Compact and Fresh start carry over from angomedia `session-hud` unchanged in behavior and copy (toasts included).
- `ui.render` on `AbovePrompt`: `const below = await next(e)` first; return `below` when `hasSurvey`, no reading, or off. Otherwise a column: `below`, then the card. Card: optional alert row (`alertText`, with a 10px red dot `Svg` that pulses), then a row of lanes column, session column, buttons column.
  - Desktop lane: label `Text color="subtle"`, the lane `Svg` (`laneSvg`/`contextSvg`, alt `"<label> N% used"`), percent `Text bold` (warm hue at warn/hot), detail `Text color="subtle" wrap="truncate-end"`. Context detail is `97k of 1M tokens`, or `—` with `1M window` when `contextPercent` is undefined.
  - Desktop session column: `Session` + bold time, `sparkSvg` (alt `Cost over the session`; context hue, or warn hue when an alert shows) once there are ≥ 3 readings, then `money · burnRate` (each part only when present).
  - Terminal: each lane is one `Text` line of label padded to 9, `terminalBar` runs colored by part (`used` and `projected` in the lane's hue, `projected` with `dimColor`, `tick` default color, `empty` `dimColor`), the percent, then detail. Cells are 20, or 10 when `bodyColumns < 80`. One session line: `Session 9m  API ≈ $0.69 · $4.60/h`, then `Opus 5.5 1M · High effort` when known. Buttons in a row after.
  - Lanes for limits only when the reading has any.
